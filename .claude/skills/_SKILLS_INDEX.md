# Skills Index (metadata-only — §29 JIT Skill Loading)
# Invoke with the Skill tool (skill: "<name>") to load full content.

- aqg-resolver: Low-context autonomous fixer triggered when the Executor is [LOCKED - AQG FAILED]. Reads test stderr, applies exact file fixes without altering business logic, and re-runs the AQG gate.
- arch-oracle: Use this skill when the user asks about git history, past decisions, why something was built a certain way, or needs to trace when/why a change was made. Provides historical awareness from git log, blame, and .ai/ memory.
- arch-review: Use this skill when the user requests an architectural review, before a major commit, or when checking blueprint alignment. Audits the codebase against architect.md for orphaned work, deviations, and top architectural risks. (Renamed from the review skill name to avoid colliding with the Engineer's tier-aware critic-review skill — E-149.)
- arch-task: Architect task lifecycle — mark P-## tasks DONE, log completion, and trigger rein-handoff to the Engineer. Use after completing any planning or blueprint session. Never leave P-## tasks open without closure.
- architectural-aligner: Use this skill when reviewing code changes for blueprint compliance, before a Tier 2/3 commit, or when the blueprint-aligner-mcp flags a deviation. Checks source code against architect.md and flags violations.
- blueprint-writer: Enforce blueprint structure before writing to .ai/blueprints/. Validates required sections (Core Concept, Data Model, API Contracts, Security, Rollback Plan, 3+ components) before any write. Blocks lazy blueprints.
- bug-reproducer: Enforces empirical validation for Tier 2/3 bug fixes. Forces creation of an isolated repro.sh or failing test that proves the bug exists before any source modification is allowed.
- ci_gate: Gate required before changing any CI/CD pipeline or deployment config. Documents the change, security implications, and rollback plan in .ai/DEVOPS.md before any edits are made.
- commit-crafter: Automates Rein commit requirements — stages changes, formats Conventional Commits with E-## task IDs and UACS stamps. Forbids --author flags and Co-authored-by trailers per Git Identity mandate.
- copilot: Delegate shell command lookups and GitHub CLI (gh) tasks to GitHub Copilot CLI. Use for shell/gh command suggestions and explanations only — not for code review, security decisions, or architecture.
- decision-recorder: Capture architectural decisions into .ai/DECISIONS.md as D-### entries. Covers design choices, trade-offs, rejected alternatives, and the constraints driving each decision. Invoke after any major architectural choice.
- dependency_gate: Gate required before adding any new major dependency (npm install, pip install, go get, etc.). Documents justification, alternatives, security track record, and license in .ai/DECISIONS.md before installation.
- digest_updater: Trigger this when DIGEST.md is stale (>3 days old), after a major sprint, or at session end. Regenerates .ai/DIGEST.md using JIT reads — only reads files that changed since the last DIGEST update. Also invoked automatically by the Stop hook.
- identity_guardian: Trigger this when handling PII, user data, secrets, API keys, or any personally identifiable information. Audits code and configs for data exposure risks, enforces secrets hygiene, and produces a PII_AUDIT.md report.
- obs_baseline: Apply observability standards (structured logging, metrics, tracing, health checks) when implementing new features or setting up DevOps pipelines.
- rein-archive: Use this skill ONLY when the user explicitly requests an archive operation. DESTRUCTIVE — moves LOG.md, COMM.md, REVIEWS.md, SESSION.md to .ai/archive/YYYY-MM/ with timestamps and re-initializes from templates. Never invoke autonomously.
- rein-debug: Enforce structured hypothesis→test→observe debugging loop for failing tests or bugs. Blocks git add until green. 3-cycle TASK_BUDGET — escalates to Architect via advisor-mcp on BUDGET_EXHAUSTED. Prevents trial-and-error token burn.
- rein-digest: Use this skill when DIGEST.md is stale (>3 days old), after a major sprint, or after running skill: rein-archive. Reads all .ai/ files and produces a concise 20-60 line project snapshot.
- rein-handoff: Produce a structured handoff packet for Architect↔Engineer transitions. Reads unread deltas from state, formats blueprint divergence and decisions into .ai/COMM.md. Use before switching agents.
- rein-incident: Record an unpredictable Rein event (MCP crash, drift, env failure, hook regression) to ~/.rein/incidents.ndjson for later aggregation. Sanitises PII; rotates monthly. Triggered by the Architect or Engineer when an action surfaces unexpected behaviour the user didn't anticipate.
- rein-insights: "Trigger the meta_analyst (E-85) to regenerate ~/.rein/INSIGHTS.md from cross-project telemetry recorded in ~/.rein/telemetry.sqlite (E-84). Use when prompted by rein-preflight staleness check (E-86) or on demand before a planning session. Read-only over telemetry; write-only over INSIGHTS.md."
- rein-log: "Append a structured entry to .ai/LOG.md after any significant action. Enforces RULES §4 mandate. Captures the session id (${CLAUDE_SESSION_ID} substitution, E-284) for cryptographic audit traceability (E-49). Checks if LOG.md exceeds 200 lines and triggers rein-archive warning if so."
- rein-migration: Workflow triggered when an Engineer needs to alter the shape of any core database (state.sqlite, telemetry.sqlite). Guides migration design, validates against ORM contracts, and manages rollback paths with ACID guarantees.
- rein-preflight: Use this skill at the start of every session in a Rein project. Executes the DIGEST-first read order (DIGEST → TASKS.md → architect.md if needed) and stamps SESSION.md.
- rein-profile: In-context profiling workflow for Node.js performance measurement. Runs node --cpu-prof / --heap-prof under Bash in a throwaway temp directory and returns structured profiling data (plus the .cpuprofile/.heapprofile files) to the performance_engineer agent.
- rein-review: Run a tier-aware critic review before committing. Tier 1 skips review. Tier 2 runs blueprint-aligner only. Tier 3 runs full parallel critics (arch + security + tests) plus security_engineer and UACS verification. Replaces the removed `rein review claude` shell command (E-34).
- rein-review-proposed-skills: Use this skill to review and promote PROPOSED self-learned skills. Lists the inert proposals staged by the meta_analyst (instinct extraction), shows each for human review, and promotes only the ones the operator APPROVES via approval-mcp. This is the human-in-the-loop activation stage of the self-learning loop (E-145).
- rein-seo: Use this skill when the user mentions "AEO", "LLM optimization", "AI search", or asks "how do I show up in AI answers". Audits content for AI Engine Optimization (AEO) and LLM Mention Optimization (LLMO) to ensure pages are discoverable and cited by AI engines.
- rein-sync-state: Use this skill when handing off work between the Architect and the Engineer, or when your context may be stale after the other agent modified .ai/ files. Forces explicit re-read of TASKS.md, architect.md, and DIGEST.md from the filesystem, bypassing conversational memory cache.
- rein-task: Manage Rein task lifecycle — mark tasks DONE, run handover, check for next tasks. Use after completing any E-## implementation. Wraps task-synchronizer-mcp and run_handover in one step.
- rein-test: Use this skill when asked to run tests, before committing, or for Tier 3 releases. Runs the project's real test command by default; --generate dispatches the headless test_engineer Tester (Claude, sonnet) to write tests; --fast runs the Tester on haiku; --vibe triggers the two-phase Vibe & Chaos audit (ux_reviewer + chaos_monkey).
- rein-triage: Runs daily or when incidents.ndjson crosses a size threshold. Invokes sre_responder agent to analyze recurring failures, draft post-mortems, and queue remediation tasks.
- rein-upgrade: Triggered periodically or on `npm audit` failures to bump packages and run test suites. Calls dependency_manager for complex migrations. Produces upgrade branches and test reports. Routes all dependency changes through critic_security before merge.
- release-manager: Handles the sprint release lifecycle — bumps package.json version, aggregates DONE tasks into CHANGELOG.md, creates a signed git tag, and optionally triggers skill: rein-archive.
- repo-oracle: Answer historical questions about the codebase — why something was built, when it changed, who decided it. Guided git log/blame and .ai/LOG.md search. Use before modifying existing code.
- review_synthesizer: Trigger after all Tier 3 audit agents complete (chaos_monkey, vibe_sentinel, security_engineer, critic_arch/security/tests). Aggregates all stamps from REVIEWS.md and LOG.md into a Release Readiness Report and writes [RELEASE_READY] or [RELEASE_BLOCKED] to LOG.md.
- scope_safety: Enforce filesystem and shell scope boundaries on every file/shell operation. Blocks path traversal, unauthorized writes, and commands not in CAPABILITIES.md. Mandatory — applied automatically to all operations.
- seo_content_checklist: Use this skill before publishing new pages or updating web content. Runs the full SEO and content compliance checklist covering title tags, meta descriptions, H1/H2 structure, canonical tags, sitemap, and GDPR requirements.
- task-planner: Gate before writing P-## or E-## tasks to TASKS.md. Enforces tier, actionable description (verb required), blueprint reference, acceptance criteria, and no circular dependencies. Blocks vague tasks.
- token-miser: Use this skill when context is growing large, before a long session, or when asked to optimize token usage. Applies progressive disclosure, context pruning, and DIGEST-first read order to minimize token cost.
- trigger-audit: Use this skill immediately after the PLAN phase and before the first WRITE operation on any E-## task. Scans staged git diff and task description for keywords that mandate agent/skill dispatches (auth, secrets, new deps, CI, endpoints). Returns a Mandatory Trigger Report checklist. Also invoke mid-task if the implementation deviates from the original plan.
- ux_template: Use this skill when designing or reviewing a UI screen or view. Generates structured UX documentation capturing purpose, entry points, layout regions, interaction states, accessibility, and mobile behavior.
